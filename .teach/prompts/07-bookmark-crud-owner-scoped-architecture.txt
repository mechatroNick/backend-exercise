## Source anchors and bounded claims

- Bookmark router/service/repository preserve authenticated user scope in database predicates.
- Tag normalization trims, lowercases, rejects blank values, deduplicates membership, and retains orphan tag rows.
- Events are post-commit hints; current snapshot behavior belongs to prompts 13–14.

## Technical style instruction

White protected-resource schematic: charcoal clients, deep-purple HTTP, brick-red current-user scope, muted-orange service/policy, royal-blue SQLite, muted-magenta post-commit event. Solid durable arrows, dashed no-op, red denied arrows; short labels only.

## Abstracted teaching intent

Teach one authenticated resource path for create/list/detail/patch/delete. The service validates and normalizes before a user-scoped repository query. The database represents bookmarks, reusable tags, and the link table. A cross-user attempt returns not-found, not an ownership leak. A material commit can publish a content-free invalidation after commit.

## Distilled Image Prompt

Flat 2D vector technical schematic on a clean white background displaying owner-scoped Bookmarks API CRUD with canonical tags. Monochromatic professional color scheme with subtle muted color accents, engineering-grade precision. No 3D effects, no gradients, no photorealism. Charcoal users, deep-purple routes, brick-red current-user badge, muted-orange service and tag funnel, royal-blue repository/SQLite, muted-magenta post-commit event.

Treat concealment and ownership as structural properties, not annotations. User A and User B start with equal visual weight but only the authenticated current-user badge may enter the service. Draw the repository boundary so every fetch, update, and delete arrow carries a tiny `user id` predicate chip. A cross-owner identifier takes the same purple Not Found envelope as an absent identifier; it must never expose an ownership comparison or a forbidden-status distinction. Put a short response edge after the service so the route is visibly thin and the service owns validation, tag normalization, timestamp decisions, and mutation policy.

Add a bottom mutation contract rail. Create has a green material-change route into persistence. Patch forks at a compact comparison diamond: no field/tag change travels a gray dashed path straight to the response and bypasses commit, updated timestamp, and invalidation; material change goes through the green commit stamp. Delete has a separate material route but does not imply automatic tag garbage collection. At the right edge, show the post-commit invalidation envelope as a small non-authoritative downstream notification—not a public event stream and not a substitute for the durable bookmark transaction. Keep tags as canonical membership: trim and normalize incoming text, reject blank values, and merge duplicates before persistence.

Wide 16:9 left-to-right layout. Two equal charcoal person cards “User A” and “User B” sit on far left. A purple “Bookmarks” route card and brick-red “Current User” badge lead to the largest orange “Bookmark Service” center card. The blue persistence cluster dominates right; the magenta event is small and downstream. Keep a purple “Not Found” envelope on the lower right of a dashed red forbidden path.

Use thick solid arrows for authenticate, mutate, normalize, persist. Use thin gray dashed arrow for no-op patch, bypassing commit/updated/event. Use magenta arrow Commit to Invalidation “publish”. Use dashed red arrow User B to Not Found “conceal”.

Use short callouts at the ownership predicate, tag funnel, materiality diamond, and commit stamp to make the four critical invariants inspectable without a separate legend. Maintain clear distance between response data and the private invalidation envelope.
