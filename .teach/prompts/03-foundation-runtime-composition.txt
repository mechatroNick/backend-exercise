## Source anchors and bounded claims

- `app.main.create_app` and `_lifespan` compose application lifecycle.
- `Settings` provides validated runtime configuration; `SystemClock` is injectable UTC time.
- `app.db.engine` creates short synchronous sessions and applies SQLite connection policy.
- Alembic, not application startup, owns schema creation. No claim is made about external deployment.

## Abstracted teaching intent

Teach that the application is deliberately inert when imported, then explicitly composed
at runtime: locked Python tooling selects dependencies; validated settings feed the
factory; lifespan owns service start/stop; a request uses an injected UTC clock and a
short SQLModel session; SQLite is reached only through configured connections. Alembic
evolves schema before runtime rather than as a hidden startup effect.
