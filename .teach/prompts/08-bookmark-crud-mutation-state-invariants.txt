## Source anchors and bounded claims

- `classify_patch`, tag policy, and repository ownership predicates define mutation outcomes.
- `created_at` stays immutable; `updated_at` changes only after material scalar/tag change.
- Missing and another-user resource paths both become not found.

## Technical style instruction

Center-focused white state schematic. Orange policy state, blue rows, green material path,
gray no-op, red forbidden ownership/cleanup, purple response, magenta post-commit hint.

## Abstracted teaching intent

Teach why PATCH is not merely a database write: tags become canonical membership, a
semantic no-op makes no write, no timestamp change, and no event; material change commits
once, advances only updated time, and publishes only afterward; all resource access carries user id in the predicate.

## Distilled Image Prompt

Flat 2D vector technical schematic on a clean white background displaying Bookmarks API mutation invariants for create, patch, delete, tags, and timestamps. Monochromatic professional color scheme with subtle muted color accents, engineering-grade precision. No 3D effects, no gradients, no photorealism. Muted-orange policy, royal-blue stored rows, forest-green material path, gray no-op path, brick-red ownership guard, deep-purple response, muted-magenta event.

Make every state transition inspectable. Draw a narrow precondition rail under the operation tabs: authenticated user id, owner predicate, payload validation, and canonical tag membership. The route may select the operation, but the orange service card owns all four checks. Use a red-barred lower alternative to show why “fetch then compare” outside the owner predicate is not the accepted design. A missing row and a row owned by someone else join the same purple 404 envelope; they must not create separate diagnostic branches.

Show timestamp and event invariants as downstream effects, never as inputs. The blue bookmark row owns a locked `created` field and a rotating `updated` field. The green material route reaches commit first, then updated and invalidation only after successful commit. The gray no-op patch path must visibly skip all three effects and still reach a valid response. The tag funnel should show normalization before comparison: whitespace disappears, duplicates collapse, blanks stop at a red reject bar, and the canonical set becomes the only membership sent to persistence. Keep the invalidation envelope internal and tiny; do not turn it into an audit log, a public feed, or an independent source of truth.
