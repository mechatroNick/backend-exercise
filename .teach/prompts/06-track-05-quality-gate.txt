TRACK 05 — MANDATORY OPENAPI, INTEGRATION TESTS, AND QUALITY GATE

Purpose: teach why the core API had to become an executable contract before bonus and
background extensions. Read with `.tracks/05-mandatory-quality-gate/SPEC.md`,
`tests/contract/mandatory_gate.py`, `tests/contract/mandatory-nodeids.txt`,
`scripts/verify-track-05.sh`, and the Track 05 evidence matrix.

ARCHITECTURE VIEW — IMAGE-GENERATION PROMPT

RENDERING BRIEF: Flat 2D vector verification-firewall schematic, 2K wide 16:9, pure-white background. Make the central gate visually solid and physical, with three inlet slots
and two controlled outlet doors. The OpenAPI tree should be a purple document with small
endpoint leaf icons; the live service should be a purple server connected to a blue
SQLite cylinder; the source tree should be slate files. Test instruments are small
orange tubes, browser/schema cards, lint brush, type magnifier, and coverage gauge—not
a noisy dashboard. Inside the gate, use three stacked stations with a green agreement
join beneath them. The extension and hardening exits remain pale/locked until the receipt
folder is green. Failure cards should be red but small, all draining down and away from
the successful path. The bottom evidence chain has physical command terminal, selector
tag, cleanup broom, and report page icons. A viewer should understand that quality proves
agreement between documents, runtime, and persistence rather than merely passing tests.
